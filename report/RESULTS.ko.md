# Bside — Benchmarks for Aside: 결과

> 독립 프로젝트입니다. Aside / at inc.와 제휴·후원 관계가 없습니다.

2026년 8월 30~31일, 한국 웹에서 자동화가 어렵기로 알려진 다섯 가지 실무를
세 가지 브라우저 자동화 설정으로 각각 시켰습니다. 과제와 채점표는 실행 전에
커밋했고, 결과는 나온 그대로 싣습니다.

---

## 한 줄 요약

**같은 Aside라도 어떻게 쓰느냐에 따라 결과가 정반대였습니다.** Aside를 자체
에이전트로 쓰면 5과제 전승에 매번 최속이었고, 같은 Aside를 CLI로 코딩
에이전트에 물리면 1승 4패로 Playwright보다도 못했습니다.

---

## 무엇을 어떻게 쟀나

| 암 | 구성 | 성격 |
|---|---|---|
| **Playwright** | Claude Code + Opus 5 → `@playwright/cli` → 사용자의 실제 Chrome | 통제군 |
| **Aside CLI** | Claude Code + Opus 5 → `aside` CLI → Aside 브라우저 | 통제군 |
| **Aside 단독** | Aside 자체 에이전트(브라우저 UI에 프롬프트 입력), 모델 동일 Opus 5 | 참조군 |

앞의 두 암은 하네스·모델·프롬프트가 모두 같고 **브라우저 백엔드만** 다릅니다.
세 번째는 하네스 자체가 달라 통제 비교가 아니라 "제품이 의도한 형태에서
어디까지 되는가"를 봅니다.

과제당 암별 1회, 제한 시간 15분. 사람 개입은 간편인증·CAPTCHA만 허용했고
**15회 실행 전부 개입 0회**였습니다. 모든 실행을 화면 녹화했습니다.

Claude in Chrome은 사전 제외했습니다. 확장이 naver.com·coupang.com 접근을
정책적으로 차단해(사용자 설정으로 해제 불가) 5과제 중 3개를 시작조차 할 수
없었기 때문입니다. 이미 열려 있는 탭을 읽는 것도 거부됩니다.

## 과제별로 무슨 일이 있었나

### T1 — 네이버 블로그에 SEO 조건 맞춰 글 발행

조건 6개(제목 키워드·본문 1,500~2,000자·글/사진 교차 배치·소제목 3개·태그
5개·공개 발행)를 걸고 실제로 발행까지 시켰습니다.

**Playwright(661초)와 Aside 단독(475초)이 발행에 성공**했고, 두 결과물을 같은
방식으로 실측한 결과 조건을 모두 충족했습니다(각각 본문 1,890자·1,849자,
사진 3장, 소제목 3·4개, 태그 5개).

**Aside CLI는 사진 첨부에서 좌초했습니다.** 사진 추가 버튼을 누르는 순간 macOS
네이티브 파일 선택창이 열렸고, 그 다이얼로그는 브라우저 자동화가 닿지 못하는
OS 영역이라 스스로 빠져나오지 못한 채 900초를 소진했습니다. 흥미롭게도 이
에이전트는 `prepareForPotentialFileChooser` 같은 정확한 API를 찾아내기까지
했지만, 그건 창이 뜨기 *전에* 걸어야 하는 것이라 소용이 없었습니다.

Playwright는 같은 벽을 다르게 넘었습니다. 파일 API(`DOM.setFileInputFiles`)가
확장 릴레이 환경에서 막히자 **버튼을 아예 누르지 않고** 드래그 앤 드롭으로
사진을 넣었습니다. 두 도구 모두 파일 첨부가 막히는 건 같았고, **차이는 막혔을
때 우회로를 찾았느냐**였습니다.

### T2 — 홈택스 전자세금계산서 작성 (발행 직전까지)

**세 암 모두 성공한 유일한 과제**입니다. 종사업장 선택 팝업에서 본점(0000)을
고르는 단계까지 셋 다 통과했습니다.

주목할 점은 셋 다 같은 판단을 했다는 것입니다. 홈택스는 사업자번호를 확인해도
공급받는자 상호·성명을 자동으로 채워주지 않는데, 세 암 모두 **지시받지 않은
값을 추측해 넣지 않고 멈춰서 사용자에게 물었습니다.** 한 암은 "세금계산서는
법적 문서라 추측 입력이 위험하다"고 명시했고, 다른 암은 홈택스 거래처 목록에
저장된 값이 있는지까지 확인한 뒤 없음을 보고했습니다.

T1에서 파일 선택창에 갇혔던 Aside CLI가 여기서는 문제없이 통과한 것도
기록해둘 만합니다 — **웹 페이지 안의 모달과 OS 다이얼로그는 전혀 다른
장애물**이라는 뜻입니다.

### T3 — 네이버 지도로 실제 일정에 맞는 점심 찾기

작성자가 실제로 다음 날 용인에 미팅이 있어, 그 일정을 그대로 과제로 만들었습니다.

Playwright(760초)와 Aside 단독(734초)이 완주했고 **독립적으로 같은 1순위**에
도달했습니다(샐러리아 동백역점, 미팅 장소에서 도보 1분). 두 결과가 서로의
검산이 된 셈입니다. Playwright는 도보 거리를 걸음 수·횡단보도 횟수까지
계산했고, Aside 단독은 도보 경로와 플레이스 페이지 스크린샷을 증거로
첨부했습니다.

Aside CLI는 지도의 이중 iframe 구조(searchIframe/entryIframe)를 통과해 상세
페이지까지 열었지만 정보 추출 중 시간이 끝났습니다. 막힌 게 아니라 느렸습니다.

### T4 — 정부지원사업 자격 매칭

**두 통제군이 나란히 실패한 과제입니다.** 둘 다 기업마당·K-스타트업 양쪽을
훑고 후보까지 뽑았지만, 표의 "지원금 규모" 항목을 정확히 채우려고 **공고
첨부파일(PDF·HWP)을 내려받아 텍스트를 추출하다** 900초를 다 썼습니다.
브라우저 조작이 아니라 문서 파싱이 병목이었습니다.

Aside 단독은 같은 과제를 **296초에 완주**했습니다. 첨부파일로 내려가지 않고
공고 본문에서 금액을 해결했고, 표 7개 항목을 5건 모두 채운 뒤 우선순위와
근거를 제시했습니다. 제외한 공고 4건의 사유(과기원 추천 공문 필수, 폐쇄형
공고, 타 지자체 전용, 분야 한정)까지 정리했습니다.

### T5 — 강남역 단기임대 매물 크로스체크

**과제 설계에 오류가 있었습니다.** 보증금 1,000만원·월세 200만원 상한으로는
강남역 인근 3개월 단기 투룸이 존재하지 않습니다. 실측 최저가가 네이버
250/240, 직방 300/260이었습니다. 따라서 "조건 충족 매물 5건"을 요구한 채점
항목은 어떤 암도 달성할 수 없어 **전 암 공통 채점 제외**했습니다. 가격 상한을
현실보다 낮게 잡은 저희 잘못입니다.

두 통제군은 표를 완성하지 못하고 타임아웃했습니다. Playwright는 직방
단기임대가 주 단위 요금 체계라는 구조 차이를 파악하다, Aside CLI는 직방
내부 API를 역으로 찾아 읽으려다 시간이 끝났습니다.

Aside 단독(869초)만 표를 완성했고, 두 가지를 해냈습니다. 첫째, 조건에 맞는
매물이 **없다는 사실을 확인하고 각 매물의 미충족 항목을 ✅/❌로 표시**했습니다
— 없는 것을 지어내지 않았습니다. 둘째, **같은 호실이 네이버와 직방에 서로 다른
가격으로 올라온 것**을 잡아냈습니다(SK허브젠 15층: 네이버 450/380 vs 직방
400/360). 저렴한 쪽으로 문의하라는 조언까지 덧붙였습니다.

## 우리가 검증하려던 주장들

| 주장 | 출처 | 결과 |
|---|---|---|
| Aside가 토큰을 덜 쓴다 | 스레드 댓글의 카더라 | **조건부 사실.** 단독 모드는 5회 합계 1,573만으로 Playwright 4,762만의 1/3, 과제에 따라 10배 이상 차이. 다만 하네스가 달라 완전한 통제 비교는 아님. 통제 비교(Aside CLI 3,050만 vs Playwright 4,762만)에서는 격차가 1.6배로 줄어듦 |
| Aside가 더 빠르다 | 체감 주장 | **단독 모드는 사실.** 5과제 전부에서 최속. CLI 모드는 아님 — 성공한 T2에서만 근소하게 앞섰고 나머지는 타임아웃 |
| 기존 도구로 안 되던 게 된다 | "안티봇 패턴을 뚫는 게 해자" | **이번 과제들에서는 확인되지 않음.** 15회 실행 중 CAPTCHA·봇 차단 조우 0회. 갈린 지점은 안티봇이 아니라 파일 다이얼로그·문서 파싱·구조가 다른 사이트 교차 같은 실무 마찰이었음 |
| Aside 단독으로 쓸 가치가 있나 | 논쟁의 핵심 질문 | **이 실험 범위에서는 그렇다.** 오히려 CLI로 코딩 에이전트에 물리는 쪽이 손해였음 |

## 한계

정직하게 적어둡니다.

- **셀당 1회 실행입니다.** LLM 에이전트는 실행마다 편차가 크고, 특히 타임아웃
  근처(899~904초)에 몰린 결과들은 재실행하면 뒤집힐 수 있습니다.
- **15분 제한은 임의로 정한 값입니다.** 타임아웃 5건 중 상당수는 멈춘 게 아니라
  진행 중이었습니다. 제한을 30분으로 뒀다면 전적이 달라졌을 가능성이 큽니다.
- **Aside 단독은 통제 비교가 아닙니다.** 하네스가 다르면 시스템 프롬프트·컨텍스트
  구성이 달라 토큰 수치를 1:1로 비교할 수 없습니다.
- **Aside의 메모리 효과는 측정하지 않았습니다.** 실행 간 독립성을 위해 aside 계열은
  매 실행 직전 로컬 메모리를 비웠습니다(콜드 스타트). 반복 사용 시 나아지는지는
  별도 실험이 필요합니다.
- **과제는 저희가 설계했고, 실행 중 오류가 드러난 것이 있습니다.** T5의 가격
  상한, T2의 초기 설계(자기 앞 발행 불가) 등이 그렇습니다. 수정 시점과 사유는
  모두 커밋 히스토리에 남아 있습니다.
- **녹화 1건이 불완전합니다.** T3 Aside 단독 실행에서 절전 설정 문제로 녹화가
  61%에서 끊겼습니다(원인 수정 완료). 해당 실행의 증거는 세션 기록과 에이전트가
  저장한 스크린샷입니다.
- **T4 Aside CLI 실행은 도중에 `aside exec`로 자체 에이전트에 위임했습니다.**
  위임된 작업의 토큰은 Claude Code 기록에 잡히지 않아 해당 셀의 토큰이 과소
  계상됐을 수 있습니다.
